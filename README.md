# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:db` 这一项（旧版键
  `urban-utility-tunnel:entries` 首次打开会自动迁移）。

## 管廊主体统一判定口径（v2）

唯一事实来源：`frontend/src/data/tunnel-policy.ts`。列表、详情面板、页脚统计、停用联动提示、
派工清单都只调用这份函数，页面不允许再各判一遍。

**适用范围**：v2 仅对改版后的新记录（`policy='v2'`）生效；改版前既有记录（`policy='v1'`）
按当时口径保留原判、状态冻结，在管廊页面以「v1 原判」标注；v1 记录首次发生新版动作时，
自生效日起切换为 v2 管理，原判留在流转日志中。

**三态判定**（优先级自上而下，基准日为今日）：

| 状态 | 判定条件 | 允许范围 |
| --- | --- | --- |
| 运行中 | 投运日期 ≤ 今日（投运只按投运日期算，不再与管线迁出挂钩） | 投运日期为合法日期 |
| 检修中 | 检修起始日 ≤ 今日 ≤ 检修截止日 | 工期 1–180 天，默认 7 天；只能自当日起登记 |
| 已停用 | 停用生效日 ≤ 今日 | 终态、优先级最高；生效日不得晚于今日；同一管廊重复停用只生效一次 |
| 待投运 | 无投运日期，或投运日期在未来 | — |

**取值区间与默认值**（越界整单驳回并逐条说明理由）：

- 舱室数量：整数 1–20，**默认 1**；填 0、负数、小数、超 20 一律驳回。
- 总长度：0.1–100000 米，最多 2 位小数。
- 检修工期：1–180 天；停用生效日：合法日期且不晚于今日。

**停用联动（同一份口径）**：停用在一次原子写入里同时落台账、流转日志和两处派工清单
（设施检修管理 / 入廊作业审批读到同一条记录）；入廊管线、在册设备、环境监测记录按
「所属管廊」编号解析，命中即展示同一份停用提示（设备转停用监护、监测保留采集按停用廊段
归档、管线限期迁出）。

**并发与重复**：每次提交带提交流水号；停用按管廊编号永久幂等，其余动作同一行同一动作
5 秒并发窗口内只认先落库的一笔，后到的按重复挡回。台账、日志、派工清单在同一次
localStorage 写入里更新。

**存量补录（一次性、幂等）**：首次打开自动执行，按管廊编号+业务发生日去重，可重复执行：

1. 先整批补录上线前纸质老记录，业务发生日取投运日期，状态沿用纸质原判（v1 冻结），
   来源标注「纸质台账整批补录」；
2. 再回填既有电子记录缺项：缺舱室数量先按竣工图纸标准断面舱数补（来源「图纸口径补录」），
   图纸也缺的临时按默认 1 补并标「图纸缺项·待核定」；既有记录状态一律不改、保留原判。
