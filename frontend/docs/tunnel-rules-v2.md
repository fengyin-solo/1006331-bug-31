# 管廊主体统一判定口径（第二版）

- 生效日期：**2026-10-07**
- 适用范围：改版后**新登记**的综合管廊记录；上线前的存量记录按当时口径**保留原判**（行上标记 `v1 老口径原判`），不按新口径重判。
- 唯一出口：`src/domain/tunnel-rules.ts`。列表、详情面板、页脚统计、管线/设备/环境监测的停用提示、派工清单文案都从这份规则取数，页面内不得另写判定。

## 1. 状态判定（只留一套）

| 状态 | 判定条件 | 允许的来源动作 |
| --- | --- | --- |
| 待投运 | 新登记统一先挂待投运（投运日期允许过去或将来） | 登记 |
| 运行中 | 经「提交投运」落账（动作校验投运日期不晚于当天），未停用 | 提交投运、完工复运；检修超计划完工日自动回运行中统计 |
| 检修中 | 运行中管廊经「安排检修」落账，且当天 ≤ 计划完工日 | 安排检修（工期 1～180 天） |
| 已停用 | 运行中/检修中管廊经「停用管廊」落账，**终态** | 停用管廊（仅一次） |

补充规则：

1. 投运**只按投运日期**判定，不再用「最后一条管线迁出日期」等第二套口径。
2. 停用是**终态**：停用后不再接受任何管廊状态动作；同一管廊重复提交停用只生效一次，第二笔按重复挡回。
3. 待投运管廊不存在「停用」；只有运行中、检修中可以停用。
4. 检修中超过计划完工日未复运的，统计口径自动按运行中计（在运管廊数不漏统）。

## 2. 取值允许区间（越界直接驳回并说明理由）

| 字段 | 允许范围 | 缺省口径 |
| --- | --- | --- |
| 管廊编号 | `TUNN-####`（≥4 位数字），全库唯一 | 无默认值，必填 |
| 舱室数量 | **1～50 的整数**；0、负数、小数、超 50 一律驳回 | 新建必须手填，**不设业务默认值**；历史缺项按第 4 节补录 |
| 总长度（米） | 0.1～200000 的正数 | 必填 |
| 结构类型 | 非空（单舱/双舱/三舱/四舱等） | 必填 |
| 投运日期 | 合法日期（YYYY-MM-DD）且不晚于当天 | 未来日期只能先登记为待投运 |
| 检修工期（天） | 1～180 的整数 | 安排检修时必填 |

驳回时逐字段给出理由（见登记弹窗字段下方红字与页脚汇总）。

## 3. 停用联动口径（管线 / 设备 / 环境监测同一份）

管廊停用在**同一事务**内完成：台账置终态、行版本 +1、动作回执落账、生成一张「停用告知单」派工单，并向三侧台账写入同一条停用口径提示：

- **入廊管线**：停止新增接入与运行确认，仅允许办理迁出；未迁出管线按待迁出挂账，通知权属单位限期迁出。
- **在册设备**：停止新增登记与运行确认，仅允许报废或随管线迁出调拨；停用期内不安排例行保养，已排保养自动撤销。
- **环境监测**：停止例行采集与正常/超标判定，点位冻结，仅保留封存前最后一次采集，停用期读数不计考核。

三侧页面的动作按钮与服务端守卫（`guardedRunAction`）用同一条规则；处理意见只写一份（`stopDispatchOpinion`），管线入口、设备台账、环境监测、派工清单页读到的内容完全一致。

## 4. 存量补录裁决（一次性迁移，`src/domain/migration.ts`）

1. **整批范围**：上线日之前的老记录，按业务发生日（管廊 = 投运日期）整批补录。
2. **补录顺序**：投运日期升序 → 管廊编号升序。早发生先落账，任何时候重跑结果一致。
3. **重复提交**：同一管廊编号两笔，只认先落账的一笔；另一笔不进台账，开「重复提交驳回单」写明理由。
4. **原判保留**：存量记录挂 v1，状态依据写「老口径原判」；新口径不重判老记录。
   - 停用老记录沿用老停用口径（末条管线迁出日）仅用于回填「停用日期」字段，不改变其已停用原判。
5. **舱室数量缺项（0/空/未登记）按图纸口径补**，来源逐字段标注：
   1. 竣工图纸标注值 —— 来源「竣工图纸」；
   2. 图纸也缺：取**同片区、同结构类型**已登记舱室数量的**中位数** —— 来源「同片区同结构推断（待核实）」；
   3. 无参照：兜底 **1** —— 来源「默认值（待核实）」。
   推断值与默认值一律开「缺项核补单」，7 个工作日内对照图纸核实，逾期按图纸口径定案。总长度缺项同口径处理。
6. 每行补录后带补录批次标记（`存量补录@2026-10-07`），缺项在单元格以 `*` 与来源悬浮提示标出。

## 5. 并发与一致性

- **同一行两笔同时提交**：动作回执幂等账册（同一 `(行, 动作)` 或业务幂等键只落一笔）+ 行版本乐观锁（后到一笔持旧版本被挡回）。判定顺序：幂等账册 → 行版本 → 状态机。
- **台账与清单同事务**：所有写操作经 `commit()` 在同一份 world 上完成，管廊台账（`tunnels` 与 `rows.tunnel` 镜像）、派工清单（`orders`）、动作回执（`receipts`）一次落账，不可能两处各算各的。
- 派工单重复回写「已处理」也只认第一次。

## 6. 验证

`scripts/verify-rules.ts` 覆盖补录顺序、重复挡回、图纸补缺、越界驳回、三态一致、停用幂等、并发挡回、两侧同口径、统计联动等 56 条断言：

```bash
node_modules/@esbuild/<平台>/bin/esbuild scripts/verify-rules.ts --bundle --platform=node --format=cjs | node
```
